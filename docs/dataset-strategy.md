# Dataset and Benchmark Strategy

## Decision

VisionGuard AI will use **MVTec AD 2** as its primary industrial anomaly-detection benchmark and **VisA** as a secondary cross-dataset robustness benchmark.

## Why MVTec AD 2 is primary

MVTec AD 2 is designed for unsupervised industrial anomaly detection and contains more than 8,000 high-resolution images across eight industrial scenarios. It provides defect-free training and validation images, a public test subset with pixel-precise anomaly annotations, and private test subsets whose ground truth is not public. Official evaluation of the private test data is performed through MVTec's evaluation server.

This design is especially suitable for VisionGuard because it reduces the risk of tuning directly against the final benchmark labels and provides an external evaluation path for final reported performance.

The dataset is released under **CC BY-NC-SA 4.0**. VisionGuard therefore treats all use of MVTec AD 2 data as non-commercial research/portfolio work, and the repository must not redistribute dataset assets unless explicitly permitted.

## Why VisA is secondary

VisA contains 10,821 images across 12 object subsets, including 9,621 normal and 1,200 anomalous samples. It includes pixel-level anomaly annotations and a broader set of industrial-style objects, including complex PCB structures and multi-instance scenes.

VisA is released under **CC BY 4.0**. It is used as a secondary benchmark to test whether conclusions reached on MVTec AD 2 generalize to another dataset rather than being benchmark-specific.

## MVTec AD

The original MVTec AD remains a useful reference benchmark with more than 5,000 high-resolution images across 15 object and texture categories and pixel-precise anomaly annotations. It is not the primary benchmark because MVTec AD 2 offers a more challenging evaluation design, including lighting-condition shifts and a private evaluation pathway.

## Evaluation protocol

### Data isolation

1. Training uses only the officially designated training data.
2. Hyperparameter selection and threshold calibration use validation data only.
3. Public test data may be used for preliminary performance estimation and debugging, but not as a substitute for validation.
4. Private MVTec AD 2 test data is reserved for final evaluation through the official evaluation server.
5. Final private-test results must not influence subsequent model tuning if they are presented as a final benchmark claim.

### Leakage controls

The data pipeline must include checks for:

- duplicate file hashes where feasible;
- accidental overlap between configured splits;
- corrupt or unreadable images;
- annotation/image mismatches;
- unexpected class/category counts;
- transformations applied differently between intended splits.

### Reproducibility

Every experiment intended for comparison must record at least:

- experiment ID;
- Git commit SHA;
- dataset name and version/source;
- category or subset;
- random seed;
- model and pretrained weights;
- input resolution;
- preprocessing and augmentation configuration;
- threshold-selection procedure;
- runtime environment and GPU where available;
- inference runtime and memory measurements where measured;
- raw metric output.

### Metrics

Metrics will be selected to match the benchmark protocol and implementation being evaluated. At minimum, VisionGuard intends to track image-level detection performance and pixel-level localization performance. Metric definitions must be documented before results are published, and framework-reported values should be independently sanity-checked where practical.

No metric is to be copied from a paper, README, leaderboard, or previous implementation and presented as a VisionGuard result. Only values generated by VisionGuard's own reproducible runs may appear in the project's Results section.

## Publication rule

A result may be published in the README only when all of the following exist:

1. committed code capable of reproducing the run;
2. committed or otherwise traceable experiment configuration;
3. a saved machine-generated metrics artifact;
4. dataset and evaluation protocol documentation;
5. review confirming the result is not a manually entered estimate.

## Current status

Dataset strategy selected. No model benchmark has yet been run or published.

# MVTec AD 2 real-dataset validation

## Scope and provenance

On 2026-08-28, the Phase 1 auditor was run against a user-supplied official
MVTec AD 2 archive. The archive remained outside the repository and was
extracted to temporary local storage. Its measured properties were:

- archive size: 32,739,596,982 bytes;
- archive SHA-256: `c0ded99ef32bfc8e352d52beb44515e5b292b8598cb963aadfa91ca0763505e4`;
- dataset license/readme: present and readable;
- license text: CC BY-NC-SA 4.0.

No publisher checksum was found during this validation, so the measured archive
hash identifies the audited bytes but does not independently prove download
authenticity.

## Initial audit and investigation

The first complete audit, using commit `85e6d73`, inspected 8,004 images and 705
masks. Image decoding, mask relationships, and configured structure completed,
but the audit failed with 337 exact SHA-256 overlaps. Every overlap paired one
`test_private` image with one `test_private_mixed` image from the same category;
there was no exact overlap involving train, validation, or public test data.

The initial implementation treated every cross-split hash match as leakage. That
assumption is not valid for these two official evaluation views. Section 3.2 of
the [MVTec AD 2 paper](https://arxiv.org/abs/2503.21622) states that the mixed
private test set depicts the same scenes as the regular private test set, with a
random selection of seen and unseen lighting conditions. Exact matches are
therefore intentional when the regular lighting condition is selected.

## Corrective action

The auditor now requires any expected hash overlap to be declared explicitly in
dataset configuration with exactly two known splits and a non-empty scientific
rationale. Such matches remain in the machine-readable duplicate list with the
classification `expected_cross_split_overlap`; they are not silently discarded.
The exception is deliberately narrow: a group must contain exactly one file from
each configured split and only one category. Extra duplicates remain errors.

The validated MVTec configuration also requires the archive's `license.txt` and
`readme.txt`. Symlinked dataset content is rejected rather than followed.

## Corrected full audit outcome

The corrected auditor was rerun from scratch over the same extracted bytes. The
command completed successfully with:

- status: passed;
- images inspected: 8,004;
- masks inspected: 705;
- errors: 0;
- warnings: 0;
- expected cross-split overlap groups: 337;
- unexpected cross-split overlap groups: 0;
- within-split duplicate groups: 0.

These values were generated by the filesystem audit. They are dataset-validation
measurements, not model metrics or benchmark results. The full JSON reports were
kept out of Git because they contain local paths and per-file hashes.

## Remaining limitations

- Exact SHA-256 matching does not detect perceptual near-duplicates.
- Private labels remain inaccessible and were not inspected.
- The auditor verifies file/mask structure and readability, not semantic label
  correctness or scientific benchmark performance.
- The archive fingerprint could not be compared with a publisher-provided
  checksum.
